# Munich District Colormap

A clickable map of Munich's 25 Stadtbezirke (districts), colored by a shortlist you keep in a Notion database. Use it while deciding where to live.

## Colors

Each district can be one of three colors:

| Color | Meaning        |
| ----- | -------------- |
| 🔴 Red    | No go          |
| 🟡 Yellow | To be explored |
| 🟢 Green  | Acceptable     |

Unset districts are shown in grey.

## How it works

1. The map is a single static `index.html` generated by `bake.py`.
2. Colors are stored in a Notion database (source of truth) — one row per district.
3. A GitHub Actions workflow rebuilds the map every 15 minutes (or on demand via **Run workflow**), pulling the latest colors from Notion.
4. The workflow publishes the generated `index.html` to the `gh-pages` branch, which GitHub Pages serves. `main` stays clean (source only). The live page can be embedded in Notion.

```
Notion database ──(bake.py)──▶ index.html ──(gh-pages branch)──▶ GitHub Pages
```

Hovering a district highlights its name; each district links to its Google Maps location.

## Setup

- Repo: `munich-district-colormap`
- Enable **GitHub Pages**: Settings → Pages → Deploy from branch → `gh-pages`, folder `/ (root)`.
- **Actions secret** `NOTION_TOKEN`: a Notion integration token with access to the districts database.
- **Actions variable** `NOTION_DB_ID` (optional): the Notion database ID. If unset, falls back to the default baked into `bake.py`.

The Notion database should have per-district rows with a `Nr` (number), `Color` (select: Red/Yellow/Green), `Map` (url), and `Notes` (text).

## Local usage

```sh
python3 bake.py        # writes index.html (uses NOTION_TOKEN from env if set)
open index.html
```

`NOTION_TOKEN` and `NOTION_DB_ID` can also be provided as environment variables.

## Structure

- `bake.py` — fetches colors from Notion and renders `index.html`
- `paths.json` — SVG paths for the 25 districts
- `.github/workflows/sync.yml` — scheduled + on-demand rebuild, publishes to `gh-pages`
- `index.html` — generated map (lives on the `gh-pages` branch, not committed to `main`)
